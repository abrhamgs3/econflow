## CI Failures — Root Cause and Fix

**Problem:** All 4 GitHub Actions checks were failing after the initial force push.

**Root cause 1 — null bytes in source files.**  
`src/econflow/core/pipeline.py` and `src/econflow/ingestion/cache.py` both
contained hundreds of `\x00` null bytes starting mid-file. Python raises
`ValueError: source code string cannot contain null bytes` on import, which
caused every pytest run to fail at collection. Origin: file corruption during
the extraction from the AI & Productivity research repository. Detection
method: `data.find(b'\x00')`. Fix: stripped all bytes from the null position
onward and replaced with `\n`.

**Root cause 2 — ruff finding 897 errors.**  
The `cli_scaffold/` directory was not excluded from ruff despite being
excluded from the wheel. It contains intentional scaffolding patterns that
violate production rules. Fix: added `exclude = ["src/econflow/cli_scaffold"]`
to `[tool.ruff]` in `pyproject.toml`. After exclusion, ran `ruff --fix`
(39 auto-fixes) and applied manual fixes for remaining E501, E701, E741, F841.

**Root cause 3 — ruff version drift between sandbox and CI.**  
After switching the CI lint job from `pip install ruff` to
`pip install -e ".[dev]"`, CI began catching 28 additional errors
(I001 import sorting, F401 unused imports, UP035/UP037 type annotation
upgrades) invisible to the sandbox's ruff build. Root cause: `ruff>=0.4`
resolved to different patch versions in different environments. Fix: ran
`ruff check --fix --unsafe-fixes` against a clean `git archive` checkout
to ensure the fixes matched exactly what CI would see.

**Root cause 4 — `pyarrow` missing from dev dependencies.**  
`tests/regression/test_helpers.py` uses `pd.DataFrame.to_parquet()`,
which requires `pyarrow` or `fastparquet`. Neither was in `[dev]` extras.
Fix: added `"pyarrow>=12.0"` to `[project.optional-dependencies] dev`.

## Architectural Decisions

**CI lint job now uses `pip install -e ".[dev]"` instead of `pip install ruff`.**  
Rationale: installs ruff from the project's own dependency spec, eliminating
version drift between local development and CI. Any future ruff upgrade is
an explicit change to `pyproject.toml`, not a silent change at install time.

**`examples/getting_started/` uses the Grunfeld (1958) dataset.**  
Rationale: embedded in `statsmodels` (zero download), 220 observations,
balanced panel, well-known in econometrics literature. The three-specification
progression (pooled OLS → entity FE → two-way FE) teaches the motivation for
fixed effects, not just the mechanics. Alternative considered: Penn World
Tables subset — rejected because PWT requires an ingestion step that introduces
EconFlow-specific configuration before the reader understands the basics.

**Repository root reduced to public-facing files only.**  
Files moved: `MIGRATION_CHECKLIST.md`, `agents/*.py`, `docs/MIGRATION_PLAN.md`,
`docs/SPRINT_MIGRATION_ROADMAP.md` → all relocated under `docs/development/`.
Rationale: first-time GitHub visitors should not encounter internal migration
artifacts at the repository root. A mature open-source project root contains
only: README, LICENSE, CHANGELOG, CITATION.cff, CONTRIBUTING.md,
CODE_OF_CONDUCT.md, SECURITY.md, ARCHITECTURE.md, pyproject.toml,
requirements.txt, uv.lock.

## Scientific Decisions

**Getting started tutorial uses the within transformation equation.**  
The demeaning form `(invest_it − invest̄_i) = β₁(value_it − valuē_i) + ...`
is shown explicitly. Rationale: the conceptual mechanism of fixed effects
(removing the entity mean eliminates all time-invariant omitted variables)
is the key learning objective. Showing the equation prevents the tutorial
from being purely mechanical.

**Coefficient interpretation: economic magnitude, not statistical significance.**  
Tutorial narrative focuses on the capital coefficient shift (0.231 → 0.310)
as evidence of omitted-variable bias, not on stars. Rationale: significance
is obvious from the table; the pedagogical point is the direction and magnitude
of the bias, which teaches *why* FE is necessary.

**Standard errors: clustered by entity throughout.**  
All three specifications use firm-clustered SE, including pooled OLS. Rationale:
this is the correct comparison — showing clustered SE in (1) and unclustered
in (2) would confound the FE vs. OLS comparison with a SE-type change.

## Technical Debt

**T1 — `getting_started` tutorial is design-only, not end-to-end runnable.**  
`config.yaml` references `entity_col` and `time_col` fields. These fields
are not yet read by the production pipeline (`src/econflow/pipeline.py`).
The pipeline currently hardcodes column names from the AI & Productivity
research config. The tutorial cannot be completed end-to-end until the
pipeline is made config-driven for entity/time column selection.
*Priority: High — this is a broken tutorial for new users.*

**T2 — `cli_scaffold/` is excluded from wheel and ruff but still tracked.**  
The directory exists in `src/econflow/cli_scaffold/` and in git history.
It is excluded from the published wheel and from linting, but is present
on disk for any `pip install -e .` user. Intent is unclear: either it should
be deleted or promoted to a real CLI module.
*Priority: Medium.*

**T3 — `dist/` artifacts are committed to git.**  
Both `.whl` and `.tar.gz` are tracked in `dist/`. For a repository not yet
on PyPI, this is acceptable temporarily, but it pollutes `git log` and
`git diff` with binary changes on every rebuild. Correct practice:
add `dist/` to `.gitignore` and build artifacts only at release time.
*Priority: Low — resolve before PyPI publication.*

**T4 — Windows `objects/maintenance.lock` recurring issue.**  
Every git write operation from the Linux sandbox triggers a lock conflict with
a Windows background process (likely VS Code's git extension or Windows
Defender). The sandbox cannot remove NTFS files it did not create.
This caused three separate blocked commit attempts today and required user
intervention each time.  
Workaround in use: user runs git operations from Windows terminal directly.
*Priority: Low — workflow friction, not a correctness issue.*

**T5 — `CITATION.cff` ORCID and affiliation are placeholders.**  
`orcid: "https://orcid.org/0000-0000-0000-0000"` and `affiliation: ""`
must be filled before submission to any journal data archive.
*Priority: High before first academic citation.*

**T6 — No end-to-end integration test.**  
The 100-test suite covers regression helpers, exception hierarchy, and
provenance recording. There is no test that runs the full pipeline
(`econflow run ...`) against the getting_started config and validates output.
The `ECONFLOW_RUN_LIVE_REGRESSION=1` flag is documented but the test file
is not confirmed to exist.
*Priority: Medium.*
